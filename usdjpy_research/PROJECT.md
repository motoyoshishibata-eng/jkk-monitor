## 1. 共通の合格基準（全Phase共通・変更禁止）

| 項目 | 基準 |
|---|---|
| 統計的有意性 | コスト・スワップ控除後で \|t\| ≥ 2 |
| プロフィットファクター | PF ≥ 1.3（控除後） |
| 取引回数 | 100回以上 |
| 期間 | 2007年起点。円高期／円安期を必ず別掲 |
| 近傍安定性 | パラメータを ±1時間・±1日 ずらしても符号が反転しない |
| 多重比較 | 名目 t 値と Bonferroni 補正後の臨界値を **両方併記** |

- 合格判定は **コスト控除後の数値のみ**。控除前は参考として併記するだけ。
- スプレッドは Phase 0-3 の **時間帯別実測値**。固定値・最小値は禁止。
- SL は必ず設定する。含み損放置・ナンピン・マーチンゲールは禁止。

実装上の対応: `common/cost.py` はスプレッド実測ファイルが無いと
例外を投げて止まる（黙って固定値に落ちない）。`common/backtest.py` は
`sl_pips=None` を明示フラグ無しに受け付けない。

## 2. Phase 0 — データ基盤（全Phaseの前提）

### 0-2 タイムゾーン検証（事前登録）

指示書 §0-2 は「切替週の週足開始時刻が1時間ずれること」を確認せよとあるが、
サーバーが GMT+3/+2 で米国DSTに追従しているなら **週の開始時刻
（日曜17:00ET）はサーバー時間で年間 00:00 固定になり、ずれない**。
ずれないことこそが前提の正しさの証拠になる。

そこで実際に検証可能な非対称性を3点、走らせる前に登録する:

| # | 検証項目 | 期待 |
|---|---|---|
| A | 米雇用統計（第1金曜）の出来高ピーク | 夏冬とも **15:30 固定** |
| B | 東京仲値（09:55 JST）の出来高ピーク | 夏 **03:55** / 冬 **02:55**（+60分ずれ） |
| C | 週の開始・終了バーの時刻 | 夏冬 **同一** |

A・B・C がすべて成立すれば、米国イベント基準の Phase 1〜3 は DST 処理不要。
**どれかが崩れたら定数を書き換えず、そのまま報告する。**

### 0-3 コスト実測（事前登録）

- MT5 バーCSVの `<SPREAD>` 列（point単位）をサーバー時間の1時間刻みで集計し、
  平均・中央値・90%点を `config/spread_finest.csv` に書き出す。
- `<SPREAD>` が無い／全て0 の場合は **固定値で代用せず失敗させる**。
- AVA 側は同形式の `config/spread_ava.csv` を手で用意する（§10-2 用）。

### 0-4 データ品質の但し書き

ファイネストが配信するヒストリカルデータは MetaQuotes 社提供のもので

→ **古い期間は「参考値」扱い**とし、直近数年の結果に重みを置く。
各Phaseのレポートは年別集計を必ず併記する。

## 3. Phase 1 事前登録 — FOMCサイクル時間

- **仮説**: 前回FOMCからの経過営業日（偶数週）に USDJPY のロング優位が乗る。
  株のリスクプレミアムが偶数週に集中する（Cieslak, Morse, Vissing-Jorgensen 2019）のと
  同型の偏りが、リスクオン＝円売りを通じて乗る可能性。
- **観測窓**: 偶数週 = day **-1〜3 / 9〜13 / 19〜23 / 29〜33**（営業日ベース、day 0 = 声明発表日）
- **約定**: サーバー時間 17:00 / **SL 120 pips**
- **検定回数**: 主検定1 + レジーム別2 + 近傍±1日2 = **5**（Bonferroni臨界 \|t\| = 2.576）
- **禁止事項**: 結果を見てから窓をずらすのは禁止。近傍チェックは符号の安定性を見るためだけに使う。
- **但し書き**: 偶数週効果は更新データのアウトオブサンプル追試で成立しなかったという
  報告がある。株で成立しても円で成立するとは限らず、株でも消えている可能性がある。

## 4. Phase 2 事前登録 — プレFOMCドリフト（発表前24時間）

- **仮説**: FOMC発表前24時間に USDJPY が一方向に偏る。
  **方向は決め打ちしない**（為替では見解が割れているため）。
  ロング方向で集計し **両側t検定** で判定する。走らせてから方向を選ばない。
- **観測窓**: 前営業日 **21:00** → 当日 **20:55**（サーバー時間。FOMCは21:00固定）
  - 内訳3分割: 21:00→翌02:00 / 02:00→09:00 / 09:00→20:55
- **SL 80 pips**（通常より広め）。**スリッページ 0 / 3 / 5 pips の3本を必ず併記**し、
  5 pips の悲観シナリオで基準割れするなら不合格とする。
- **21:00 の発表をまたぐ保有は設計から外す。**
- **検定回数**: 全窓1 + 内訳3 + レジーム別2 = **6**（Bonferroni臨界 \|t\| = 2.638）
- **構造的制約**: 定例FOMCは年8回。2007年起点でも取引回数は **約160回** が上限で、
  レジーム別に割ると 100 回を割る。その場合は「n不足で判定不能」と書き、基準は下げない。

## 5. Phase 3 事前登録 — NYオプションカット後のレジーム変化

- **仮説**: サーバー **17:00**（NY10:00、年間固定）を境にボラと方向性の性質が変わる。
  カット前は大口ストライクに引き寄せられて値動きが抑制され、カット後に外れてブレイクする。
- **観測窓**: カット前1時間 = 16:00台 / カット後1時間 = 17:00台
- **閾値（走らせる前に固定）**:
  - 「レンジが狭い日」= カット前1時間のレンジが **直前20営業日の下位25パーセンタイル以下**（当日を含まない）
  - ブレイク判定幅 = カット前1時間の **高値+3pips / 安値-3pips**
  - 決済 = カット後1時間の終わり（17:59）
  - SL = レンジ幅 + 3pips（最低 20 pips）
- **設計上の注意**: 上下両方に逆指値を置くため、同日に両方成立する「往復ビンタ」も
  そのまま損益に入れる。都合の良い片方だけ数えない。
- **検定回数**: ボラ比較1 + ブレイク1 + 方向一致/逆行2 + レジーム別2 = **6**
- オプション建玉データは使わない（price action のみ）。

## 6. Phase 4 事前登録 — くりっく365建玉

- **仮説**: 日本の個人投資家（逆張り寄り）の建玉偏りが極端になると、
  その方向に踏み上げ／投げが発生する。CFTC建玉（海外投機筋・順張り寄り）とは
  性質が逆なので、検証済みの CFTC フィルターとは別の情報を持つはず。
- **指標**: 買建玉比率 = long/(long+short) の **250営業日 Zスコア**（当日を含まない）
- **閾値（拡張禁止）**:
  - Zスコア閾値は **±1.5 と ±2.0 の2通りのみ**
  - 保有期間は **1日・5日・20日の3通りのみ**
  - 方向2通り → **検定回数 = 2 × 3 × 2 = 12**（Bonferroni臨界 \|t\| = 2.865）
- **主仮説の方向**: Z ≤ −閾値（個人が売り越し極端）→ ロング（踏み上げ）
- **先読み防止**: 日報は翌営業日午前に更新されるため、シグナル日の **翌営業日** に約定させる。
- **新規性の確認**: CFTC建玉との相関（水準・変化幅）を必ず出す。
  \|相関\| > 0.7 なら新規性なしとして打ち切り。個人が逆張りなら **負の相関** が出るのが自然。
- **合格時の実装**: CFTCフィルターと同じく **ロット調整型**。
  ON/OFF型は前例で口座損益が悪化しているため採用しない。

## 7. Phase 5 事前登録 — 月末リバランス量推定（UBS修正版）

- **仮説**: 月末の為替フローは方向だけでなく必要リバランス額を推定でき、
  推定量の大きさがリターンの大きさと対応する。
- **UBSの修正がこのPhaseの本体**: 月全体の相対リターンで最後X日を予測すると
  説明力を過大評価する。「月末X日前までの相対リターンで、最後のX日を予測」に改める（X=3）。
  既存の「S&P騰落率条件付き月末Fix」は月全体を使っていた可能性が高く、
  それがまさに過大評価のパターン。**旧来版も併走させて R² の差を出す。**
- **推定式**: `estimate = 0.50×(米株−日株) + 0.80×(米債−日債)`
  （株ヘッジ比率50%・債券80%。債券は total return 指数を使うこと）
- **方向**: 米国資産アウトパフォーム → ヘッジ必要額増 → ドル売り円買い →
  **売買方向 = −sign(estimate)**
- **閾値**: 推定量の絶対値で5分位に分け **上位1分位のみ** エントリー
- **FIX版**: ロンドン16時FIX 前後2時間のみ保有する版も併記。
  FIXのサーバー時刻は英米DSTのズレで **18:00 / 19:00 を行き来する**（3月下旬・10月下旬）。
  18:00 固定で回すとこの期間の取引が1時間ずれる。
- **介入日は必ず別掲**し、除いた数値も出す（介入が入るとモデルは壊れるため）。
- **検定回数**: 回帰1 + 上位分位1 + FIX版1 + 介入除外1 + 旧来版比較1 + レジーム別2 → **8** で補正。

## 8. Phase 6 事前登録 — 四半期末のドル調達需給

- **仮説**: 四半期末・年末の規制上のバランスシート制約によるドル調達需給がスポットに波及する。
- **観測窓**: 四半期最終営業日を day 0 とし営業日 **±5**。集約窓は **day −3〜0**。
- **方向**: 決め打ちしない（両側検定）。**SL 100 pips**、約定サーバー17:00。
- **別掲**: 12月末（年末）と 3/6/9月末 / **2015年前後**（日銀レビューが指摘する構造変化）
- **検定回数**: day別11 + 集約1 + 年末2 + 2015年前後2 = **16**
- **構造的制約**: 四半期末は年4回。2007年起点でも取引回数は **最大80回程度** で、
  100回基準を原理的に満たせない。day別の日次集計（n≈880）は基準を満たすが、
  売買単位では n 不足になる。基準を下げず「判定不能」と書く。
  月末も含めれば n は増えるが、それは Phase 5 の領域であり、
  ここで窓を広げると事前登録の意味がなくなる。
- **打ち切り判断**: 日付ダミーで何も出なければ、ベーシスの有料データは買わない。早めに打ち切る。
