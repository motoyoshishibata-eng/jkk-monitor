## 1. 共通の合格基準（全Phase共通・変更禁止）

| 項目 | 基準 |
|---|---|
判定方法は **仮説の形で2本立て**（v1.1 差分4）。

| 検証の種類 | 判定方法 |
|---|---|
| 総当たり探索型（候補が多数） | n ≥ 100 + \|t\| ≥ 2 + PF ≥ 1.3 + Bonferroni補正 |
| 事前登録された単一仮説のイベントスタディ | **パーミュテーション検定** + PF ≥ 1.3 |

該当: Phase 1・2・3・5・6 = イベントスタディ / Phase 4 = 総当たり探索型（12通りの格子）

### パーミュテーション検定の仕様（v1.1 差分4）

1. 実測の効果量（コスト控除後の1取引あたり平均損益）を計算
2. イベント日をランダムな営業日に置き換えて同じ計算を **10,000回** 実施
   - 曜日・月の分布を実測と揃えて層化抽出する（FOMCは火水に偏るため、
     完全ランダムだと帰無分布が歪む）
   - 層内は非復元抽出。候補が足りない層のみ復元抽出に落とし、その旨をレポートに残す
3. 実測がランダム分布の何パーセンタイルかを報告
4. **合格基準: 片側 2.5パーセンタイル以内**（両側5%相当）

これは基準の緩和ではなく、判定方法を仮説の形に合わせる修正。
**PF ≥ 1.3・コスト控除後・円高期/円安期別掲の要件はすべてそのまま維持する。**

### 共通要件（種類によらず維持）

| 項目 | 基準 |
|---|---|
| プロフィットファクター | PF ≥ 1.3（コスト控除後） |
| 期間 | 2007年起点。円高期／円安期を必ず別掲 |
| 近傍安定性 | パラメータを ±1時間・±1日 ずらしても符号が反転しない |
| 多重比較 | 総当たり型では名目 t 値と Bonferroni 臨界値を **両方併記** |

### レジーム別掲の扱い（v1.1 差分4）

- n ≥ 30: 数値を出すが **「参考値」ラベル**を付け、単独では合否判定に使わない
- n < 30: **「n不足のため算出せず」** と明記。無理に数字を出さない

- 合格判定は **コスト控除後の数値のみ**。控除前は参考として併記するだけ。
- スプレッドは Phase 0-3 の **時間帯別実測値**。固定値・最小値は禁止。
- SL は必ず設定する。含み損放置・ナンピン・マーチンゲールは禁止。

実装上の対応: `common/cost.py` はスプレッド実測ファイルが無いと
例外を投げて止まる（黙って固定値に落ちない）。`common/backtest.py` は
`sl_pips=None` を明示フラグ無しに受け付けない。

## 2. Phase 0 — データ基盤（全Phaseの前提）

### 0-2 タイムゾーン検証（事前登録）

指示書 §0-2 は「切替週の週足開始時刻が1時間ずれること」を確認せよとあるが、
サーバーが GMT+3/+2 で米国DSTに追従しているなら **週の開始時刻
（日曜17:00ET）はサーバー時間で年間 00:00 固定になり、ずれない**。
ずれないことこそが前提の正しさの証拠になる。

そこで実際に検証可能な非対称性を3点、走らせる前に登録する:

| # | 検証項目 | 期待 |
|---|---|---|
| A | 米雇用統計（第1金曜）の出来高ピーク | 夏冬とも **15:30 固定** |
| B | 東京仲値（09:55 JST）の出来高ピーク | 夏 **03:55** / 冬 **02:55**（+60分ずれ） |
| C | 週の開始・終了バーの時刻 | 夏冬 **同一** |
| D | ロンドン16時FIX の出来高ピーク（★最も識別力が高い） | 通常期 **18:00** / 英米DSTギャップ期間 **19:00** |

(D) は EU と米国の DST 切替日のギャップを使う（v1.1 差分1で追加）:

| 期間 | 期待値 |
|---|---|
| 通常期（両地域が揃っている） | 18:00 |
| 3月第2日曜 〜 3月最終日曜（米のみ夏時間） | **19:00** |
| 10月最終日曜 〜 11月第1日曜（EUのみ冬時間） | **19:00** |

ここが確認できれば「サーバーは米DSTに追従し、EUのDSTには追従しない」が確定する。
既存のロンドンFIX EA で対処した「秋ズレ」と同じ現象なので、整合するはず。

A・B・C・D がすべて成立すれば、米国イベント基準の Phase 1〜3 は DST 処理不要。
**どれかが崩れたら定数を書き換えず、そのまま報告する。**

なお、サーバーが GMT+2 固定で DST 非追従だった場合は夏の週開始が日曜23:00になるので、
(C) にも識別力はある（ずれないことが前提の正しさの証拠になる）。

## 3. Phase 1 事前登録 — FOMCサイクル時間

- **仮説**: 前回FOMCからの経過営業日（偶数週）に USDJPY のロング優位が乗る。
  株のリスクプレミアムが偶数週に集中する（Cieslak, Morse, Vissing-Jorgensen 2019）のと
  同型の偏りが、リスクオン＝円売りを通じて乗る可能性。
- **観測窓**: 偶数週 = day **-1〜3 / 9〜13 / 19〜23 / 29〜33**（営業日ベース、day 0 = 声明発表日）
- **約定**: サーバー時間 17:00 / **SL 120 pips**（1時間足で判定。SL到達の判定は M1 と同じ答えになる）
- **判定**: パーミュテーション検定（10,000回・曜日/月/**保有営業日数**を層化・片側2.5%以内）
  + PF ≥ 1.3。保有日数の違う窓を混ぜると帰無分布が別物になるので層に含める
- **検定回数**: 主検定1 + レジーム別2 + 近傍±1日2 = **5**
- **禁止事項**: 結果を見てから窓をずらすのは禁止。近傍チェックは符号の安定性を見るためだけに使う。
- **但し書き**: 偶数週効果は更新データのアウトオブサンプル追試で成立しなかったという
  報告がある。株で成立しても円で成立するとは限らず、株でも消えている可能性がある。

## 4. Phase 2 事前登録 — プレFOMCドリフト（発表前24時間）

- **仮説**: FOMC発表前24時間に USDJPY が一方向に偏る。
  **方向は決め打ちしない**（為替では見解が割れているため）。
  ロング方向で集計し **両側t検定** で判定する。走らせてから方向を選ばない。
- **観測窓**: 前営業日の **発表時刻** → 当日の **発表5分前**
- **発表時刻は年間固定ではない（v1.1 差分2）。時期テーブルで引く:**

  | 時期 | 声明の発表時刻(ET) | サーバー時刻 |
  |---|---|---|
  | 2007 〜 2011年3月 | 14:15 | **21:15** |
  | 2011年4月 〜 2013年3月12日・記者会見なし | 14:15 | 21:15 |
  | 2011年4月 〜 2013年3月12日・記者会見あり/不明 | **要確認** | **時刻不明 → 除外** |
  | 2013年3月13日 〜 現在 | 14:00 | **21:00** |

  ET → サーバー時刻は年間固定で **+7時間**（EDT=UTC-4 & サーバー=UTC+3 /
  EST=UTC-5 & サーバー=UTC+2）。定数直書きはせず `events.announcement_server_time()`
  で日付ごとに引く。「要確認」を推測で埋めることは禁止。除外件数はレポートに残す。
  - 内訳3分割: 発表時刻→翌02:00 / 02:00→09:00 / 09:00→発表5分前
- **SL 80 pips**（通常より広め）。**スリッページ 0 / 3 / 5 pips の3本を必ず併記**し、
  5 pips の悲観シナリオで PF が基準割れするなら不合格とする。
- **発表の瞬間をまたぐ保有は設計から外す。**
- **必須分割（v1.1 差分3）**: ① 記者会見あり ② 記者会見なし ③ 全会合（参考）の
  3群を**必ず別掲**する。全部混ぜた集計だけを出すのは不可。
  NY連銀の追試では、新しいサンプルで大きな超過リターンが残るのは記者会見のある
  会合のみで、会見なし会合では証拠が見られない。2019年以降は全会合に会見があるため
  分割が実質的に効くのは **2011〜2018年**。ここを混ぜると効果があっても希釈される。
  SEP公表会合かどうかも副次的に記録する（判定には使わない）。
- **判定**: パーミュテーション検定（10,000回・曜日/月を層化・片側2.5%以内）+ PF ≥ 1.3
- **検定回数**: 全窓1 + 内訳3 + レジーム別2 = **6**
- **構造的制約**: 定例FOMCは年8回。2007年起点でも取引回数は **約160回** が上限。
  v1 の n≥100 基準ではレジーム別に割った時点で判定不能だったが、
  v1.1 差分4 でパーミュテーション検定に切り替えたことで主検定は判定可能になった。
  レジーム別は n≥30 なら参考値、n<30 なら算出せず。

## 5. Phase 3 事前登録 — NYオプションカット後のレジーム変化

- **仮説**: サーバー **17:00**（NY10:00、年間固定）を境にボラと方向性の性質が変わる。
  カット前は大口ストライクに引き寄せられて値動きが抑制され、カット後に外れてブレイクする。
- **観測窓**: カット前1時間 = 16:00台 / カット後1時間 = 17:00台
- **閾値（走らせる前に固定）**:
  - 「レンジが狭い日」= カット前1時間のレンジが **直前20営業日の下位25パーセンタイル以下**（当日を含まない）
  - ブレイク判定幅 = カット前1時間の **高値+3pips / 安値-3pips**
  - 決済 = カット後1時間の終わり（17:59）
  - SL = レンジ幅 + 3pips（最低 20 pips）
- **設計上の注意**: 上下両方に逆指値を置くため、同日に両方成立する「往復ビンタ」も
  そのまま損益に入れる。都合の良い片方だけ数えない。
- **判定**: パーミュテーション検定（10,000回・曜日/月を層化・片側2.5%以内）+ PF ≥ 1.3。
  帰無仮説は「狭レンジという条件に意味はなく、どの営業日に仕掛けても同じ」。
  全営業日に同じ仕掛けをした1日あたり損益を候補とし、狭レンジ日と同じ日数を再抽出する。
  1本も成立しなかった日は損益0として候補に残す（不発も戦略の一部なので落とさない）。
- **検定回数**: ボラ比較1 + ブレイク1 + 方向一致/逆行2 + レジーム別2 = **6**
- オプション建玉データは使わない（price action のみ）。

## 6. Phase 4 事前登録 — くりっく365建玉

- **仮説**: 日本の個人投資家（逆張り寄り）の建玉偏りが極端になると、
  その方向に踏み上げ／投げが発生する。CFTC建玉（海外投機筋・順張り寄り）とは
  性質が逆なので、検証済みの CFTC フィルターとは別の情報を持つはず。
- **指標**: 買建玉比率 = long/(long+short) の **250営業日 Zスコア**（当日を含まない）
- **閾値（拡張禁止）**:
  - Zスコア閾値は **±1.5 と ±2.0 の2通りのみ**
  - 保有期間は **1日・5日・20日の3通りのみ**
  - 方向2通り → **検定回数 = 2 × 3 × 2 = 12**（Bonferroni臨界 \|t\| = 2.865）
- **主仮説の方向**: Z ≤ −閾値（個人が売り越し極端）→ ロング（踏み上げ）
- **先読み防止**: 日報は翌営業日午前に更新されるため、シグナル日の **翌営業日** に約定させる。
- **新規性の確認**: CFTC建玉との相関（水準・変化幅）を必ず出す。
  \|相関\| > 0.7 なら新規性なしとして打ち切り。個人が逆張りなら **負の相関** が出るのが自然。
- **合格時の実装**: CFTCフィルターと同じく **ロット調整型**。
  ON/OFF型は前例で口座損益が悪化しているため採用しない。

## 7. Phase 5 事前登録 — 月末リバランス量推定（UBS修正版）

- **仮説**: 月末の為替フローは方向だけでなく必要リバランス額を推定でき、
  推定量の大きさがリターンの大きさと対応する。
- **UBSの修正がこのPhaseの本体**: 月全体の相対リターンで最後X日を予測すると
  説明力を過大評価する。「月末X日前までの相対リターンで、最後のX日を予測」に改める（X=3）。
  既存の「S&P騰落率条件付き月末Fix」は月全体を使っていた可能性が高く、
  それがまさに過大評価のパターン。**旧来版も併走させて R² の差を出す。**
- **推定式**: `estimate = 0.50×(米株−日株) + 0.80×(米債−日債)`
  （株ヘッジ比率50%・債券80%。債券は total return 指数を使うこと）
- **方向**: 米国資産アウトパフォーム → ヘッジ必要額増 → ドル売り円買い →
  **売買方向 = −sign(estimate)**
- **閾値**: 推定量の絶対値で5分位に分け **上位1分位のみ** エントリー
- **FIX版**: ロンドン16時FIX 前後2時間のみ保有する版も併記。
  FIXのサーバー時刻は英米DSTのズレで **18:00 / 19:00 を行き来する**（3月下旬・10月下旬）。
  18:00 固定で回すとこの期間の取引が1時間ずれる。
- **介入日は必ず別掲**し、除いた数値も出す（介入が入るとモデルは壊れるため）。
- **判定**: パーミュテーション検定（10,000回・片側2.5%以内）+ PF ≥ 1.3。
  ここでの置換は日付ではなく **推定量そのものの並べ替え**。推定量を月末どうしで
  入れ替えて「上位分位の選択」と「方向の決定」をやり直す。月末という枠を固定した
  まま「推定量に情報があるか」だけを検定できるのでこちらが素直。

## 8. Phase 6 事前登録 — 四半期末のドル調達需給

- **仮説**: 四半期末・年末の規制上のバランスシート制約によるドル調達需給がスポットに波及する。
- **観測窓**: 四半期最終営業日を day 0 とし営業日 **±5**。集約窓は **day −3〜0**。
- **方向**: 決め打ちしない（両側検定）。**SL 100 pips**、約定サーバー17:00。
- **別掲**: 12月末（年末）と 3/6/9月末 / **2015年前後**（日銀レビューが指摘する構造変化）
- **判定**: パーミュテーション検定（10,000回・曜日/月を層化・片側2.5%以内）+ PF ≥ 1.3
- **プール検定（v1.1 差分4）**: 四半期末のドル調達は USD 側の現象なので
  **EURUSD / GBPUSD / AUDUSD をプールして検定してよい**。円クロスは円側要因が
  混入するのでプールに入れない。
  - プールで有意 → USDJPY 単体で再確認 → 単体でも同符号なら合格
  - プールで無意 → **Phase 6 打ち切り**（USDJPY単体を深追いしない）
  - 1回の置換では全ペアに同じランダム日付を使う（ペア間の相関を保たないと
    帰無分布の分散が過小になり、有意に見えすぎるため）
  - 寄与は候補日全体で標準化してから足す（pips のスケールがペアで違うため）
- **検定回数**: day別11 + 集約1 + 年末2 + 2015年前後2 = **16**
- **構造的制約**: 四半期末は年4回で取引回数は最大80回程度。v1 の n≥100 基準では
  原理的に判定不能だったが、v1.1 差分4 で解消。基準を緩めたのではなく、
  検定方法を仮説の形に合わせただけ。PF≥1.3 等の要件は維持する。
- **打ち切り判断**: 日付ダミーで何も出なければ、ベーシスの有料データは買わない。早めに打ち切る。
